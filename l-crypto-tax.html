📖 Captured Lessons by Category 10 Practical Rules
01 A chat's confident explanation is not evidence
H

Claude Desktop summarized tool results into prose and invented mechanisms: it claimed a bridge failed on an "asset mismatch (ETH vs wETH)" when the canonical-asset registry (engine/bridge.py) resolves WETH→ETH and the real cause was a wallet-label mismatch; it claimed unpaired legs were in an "UNRESOLVED queue" (which only exists in on-chain staging, not CSV); and it reported an AES-SIV key as "32 bytes / 256-bit" when it is 64 bytes.

Lesson: When a chat cites a reason, treat it as a Hypothesis To Verify, not a fact. Reproduce with the tool directly (pure call, MCP Inspector, or Python invoke) — never trust the narrative.
02 The numbers the tool returns are always correct; the interpretation is where lies form
H T

Every numeric/flag fabrication traced to the model filling gaps around the numbers: gl_balance:"0" → it needed to name accounts; valid:true → it needed a schema. The raw output was accurate every time. Fix the explanation layer, not the engine.

Lesson: An "I don't know" from the model is a debugging asset. When the model stops explaining, start reading the stack trace.
03 Fabrication can hide real bugs — and faithful reporting finds them
B

Before the fidelity contract, the model glossed the encrypt failure as a "server-side implementation issue", masking a genuine defect: security_encrypt_field crashed with NameError: name 'os' is not defined (os used but never imported). Once the contract forced quoting raw errors, the bug was visible and fixed in minutes.

Lesson: Faithful, unembellished raw error reporting uncovers masked defects immediately.
04 A one-line runtime dependency omission is invisible until a "success" path hits it
D

The XSD validator (validate_xsd) was implemented but (a) lxml was missing in pyproject.toml and (b) never wired into validate(). dac8_generate_report returned valid:true from structural rules only, and the chat upgraded that to "fully conformant to the OECD schema". Both flaws were found by testing the public surface.

Lesson: Document and test the public surface (MCP tool outputs), not just internals. If a validator exists but is unreachable, the consumer sees silence where a failure should be.
05 Encode trust rules in the server, not in a per-conversation prompt
S

A pasted prompt worked only for that specific chat window. Baking the Fidelity Contract into the MCP server's instructions field (MCPServer, server.py) forces it to load into every session automatically.

Lesson: Server-enforced contracts beat per-conversation prompts for anything that must always hold across all client sessions.
06 A "validation" result needs to name what it validated
B V

After wiring XSD validation, the tools return xsd_valid and schema (DAC8CARFMessage.xsd (OECD CARF v1)). The contract rule says valid:true is not a conformance claim unless the output names the schema. Ground truth in the output prevents overclaiming.

Lesson: Validation output must name the schema it validates against to be meaningful and verifiable.
07 Git hook failures spew sed noise and hide behind exit 0
G

The pre-commit hook's attribution stripper broke because / (sed's default delimiter) collided with pattern slashes (// Generated by Claude.*) → bad flag in substitute command on every commit. Because it was masked with exit 0, commits still succeeded silently.

Lesson: When a hook prints errors but commits succeed, check for delimiter collisions and || true / exit 0 masking. Fix: use a safe delimiter (s|pattern||).
08 Git surgery needs reflog awareness
G

Resetting HEAD~1 twice overstepped back past the intended commit. While reflog and origin/main made recovery straightforward, a git reset --hard with uncommitted docs would have destroyed work permanently.

Lesson: Prefer git reset --soft/mixed to specific commit SHAs, and confirm git status clean before and after.
09 Sample-driven testing catches data-quality traps
T

Imported transfer legs with mismatched wallet labels exposed that (a) the matcher is deliberately conservative, (b) canonical-asset logic matters for reasons, and (c) warnings surface unpaired legs that chat prose would otherwise mask as "unresolved".

Lesson: Maintain a small, dirty, adversarial CSV in data/ to test conservative matching, edge cases, and canonical asset resolution.
10 Documentation follows the incident pattern
O

Three dedicated documents mirror the recorded failure incidents: docs/MCP_SETUP.md (connection guide), docs/PLAYBOOK.md (trap tests for fabrication), and this retrospective. Future sessions can localize fabrications in minutes using T1–T7 prompts.

Lesson: Documentation should directly reflect real incident patterns with localized test prompts to verify system trust boundaries.
⚡ Executive Summary (TL;DR)
• Tool output is ground truth; chat prose is always a hypothesis to verify.
• When a chat cannot explain, that is a signal to inspect the stack trace and code.
• Test the exported surface (MCP tools), not just isolated internal logic.
• Server-enforced contracts beat per-conversation prompt instructions.
• Validation output must name the exact schema it validated against.
• Silent git hook failures will persist; test hook scripts and commits explicitly.
• Git surgery requires reflog awareness and soft/mixed reset discipline.
• Sample-driven testing with dirty CSVs catches data-matching traps early.
